# TimeCalc 开发检查清单（Checklists）

> 版本：v0.2
>
> 状态：待评审，M1 启动前生效
>
> 用途：把 [产品需求文档](requirements.md) 的验收标准与非功能需求转成可逐项勾选的明细清单，供功能开发、Pull Request、里程碑验收与发布前检查使用。流程级门禁见 [开发全流程 SOP](development-sop.md) 附录 D，本文件提供逐项明细。

## 1. 使用说明

- 每项以 `- [ ]` 勾选；用于里程碑验收或发布检查时，应在该项旁注明证据（测试命令、操作路径、演练结果或截图）。
- 各节标题标注的 P0/P1 与 PRD 一致：**MVP 对外发布前，P0 项必须全部通过**；P1 仅检查当前里程碑明确选中的功能，未选中的 P1 项标记为「不适用」而不是失败（PRD §12）。
- 验收时同时对照 PRD §4.3「明确不做」清单，防止范围蔓延。
- 勾选顺序：功能开发用 §2 对应小节 + §4/§5；PR 提交用 §6；里程碑结束用 §11 + §3 流程走查；发布前用 §10 + §9。
- 涉及日期、时区、数据库迁移、跨多表写入或备份恢复的适用项，都必须有自动化测试佐证，不能只靠手动验证。

## 2. 功能验收清单（按 FR 逐项）

### 2.1 FR-1 目标与倒计时（P0）

- [ ] 可创建、编辑、归档、删除目标；名称与截止日期为必填项（FR-1.1）。
- [ ] 倒计时按本地日期计算，不按小时取整；截止日当天显示「今天截止」（FR-1.2）。
- [ ] 截止日已过且未归档时，显示「已逾期 N 天」（FR-1.3）。
- [ ] 可主动标记目标为「已完成」或「已放弃」，两者都停止逾期提醒（FR-1.4）。
- [ ] 一个任务必须属于一个目标，可选属于一个科目/分组（FR-1.5）。
- [ ] 创建合法目标后，首页立即出现目标卡片与正确倒计时（验收）。
- [ ] 截止日为今天、昨天和跨年日期时显示正确（验收）。
- [ ] 删除目标前有二次确认，并明确提示将同时删除其任务（验收）。
- [ ] 归档目标不删除历史数据（验收）。
- [ ] 应用重启后，目标数据与状态保持一致（验收）。

### 2.2 FR-2 里程碑（P1）

- [ ] 可在目标下添加、编辑、完成和删除里程碑（FR-2.1）。
- [ ] 里程碑日期晚于目标截止日时，保存前给出阻断提示（FR-2.2）。
- [ ] 首页仅展示最近的一个未完成里程碑，完整列表在目标详情中展示（FR-2.3）。

### 2.3 FR-3 任务与日历（P0）

- [ ] 任务字段含标题、计划日期、预估分钟数、完成状态，以及可选的备注与科目（FR-3.1）。
- [ ] 可在今日列表或日历中创建、编辑、删除和完成任务（FR-3.2）。
- [ ] 可将未完成任务延期到指定日期；快捷操作默认延期至下一可用日（FR-3.3）。
- [ ] 日历显示每日任务数、完成数和预估总时长（FR-3.4）。
- [ ] 当日预估总时长超过可用时长时显示「超出 X 分钟」，不能只依赖红色表达（FR-3.5）。
- [ ] 可为历史日期补录任务和完成记录（FR-3.6）。
- [ ] 次日处理昨日未完成任务时由用户确认，不自动改变原计划（FR-3.7）。
- [ ] 完成或延期任务后，今日列表、日历和统计在同一操作周期内同步更新（验收）。
- [ ] 预估时长仅接受 1～1440 分钟整数；非法输入有明确错误提示（验收）。
- [ ] 延期操作保留任务内容、归属和预估时长，并记录原计划日期（验收）。
- [ ] 没有任务的日期不会显示为过载或完成率 0%（验收）。

### 2.4 FR-4 检查项与重复任务（P1）

- [ ] 任务可包含可排序的检查项；任务完成时，未完成检查项需二次确认（FR-4.1）。
- [ ] 重复规则仅支持每天、每周指定星期和每隔 N 天（FR-4.2）。
- [ ] 重复任务为「模板 + 实例」模型，仅预生成未来 30 天实例，并在窗口临近时滚动生成（FR-4.3）。
- [ ] 修改重复规则时，用户必须选择「仅修改未来实例」或「仅修改模板」；已完成实例不被覆盖（FR-4.4）。
- [ ] 编辑重复任务时可同步修改标题、科目、预估时长与起始日期，未来实例按新基础信息重新生成（FR-4.4 扩展，M2 迭代）。
- [ ] 停止重复后不再生成新实例，历史实例保留（FR-4.5）。
- [ ] 删除某个重复实例后，后续滚动生成不得重新生成该日期（墓碑，schema v5 验收）。

### 2.5 FR-5 手动计划与负载（P0）

- [ ] 可在日历中拖动任务调整日期；拖动失败时恢复原位置并提示原因（FR-5.1）。
- [ ] 计划负载按「当日未完成任务预估时长之和」计算（FR-5.2）。
- [ ] 目标详情展示剩余任务时长、剩余可用天数和建议日均时长（FR-5.3）。
- [ ] 建议日均时长超过每日可用时长时，显示计划风险，并建议延长截止日、减少任务或增加可用时间（FR-5.4）。
- [ ] 系统只提出建议，不自动删除任务或修改截止日期（FR-5.5）。

### 2.6 FR-6 AI 辅助生成计划（P1）

前置条件：已配置受支持 Provider 的 API Key，且网络可用；无 AI 时手动计划闭环完整可用。

- [ ] AI 输入至少包含目标、截止日期、任务/学习内容、每日可用时长和不可用日期（FR-6.1）。
- [ ] 强度选项为「轻量、均衡、紧凑」并展示对应负载解释；无「地狱」等压力暗示文案（FR-6.2）。
- [ ] AI 输出先解析为结构化草稿，并校验日期范围、时长和必填字段（FR-6.3）。
- [ ] 可在草稿中编辑、删除、调整日期，并选择全部应用或取消（FR-6.4）。
- [ ] 仅用户确认后写入正式任务；应用失败时不得写入部分计划（FR-6.5）。
- [ ] 生成页面明确提示「生成内容可能不准确，请确认工作量与日期」（FR-6.6）。
- [ ] 连接测试只验证鉴权和一次最小请求；余额和模型列表仅在 Provider 提供相应接口时展示（FR-6.7）。
- [ ] 网络不可用或未配置 Key 时，展示原因和手动排程入口，而非仅将按钮置灰（FR-6.8）。
- [ ] AI 返回非法 JSON、超时或部分字段缺失时，正式任务库不产生脏数据（验收）。
- [ ] 草稿中存在截止日之后的任务时，阻止应用并标出问题项（验收）。
- [ ] 用户取消草稿后，原有计划不发生变化（验收）。
- [ ] 日志不得记录 API Key、完整请求正文或用户隐私内容（验收）。

### 2.7 FR-7 进度反馈（P0/P1）

- [ ]（P0）首页展示今日完成数/总数、今日已完成预估时长和目标剩余工作量（FR-7.1）。
- [ ]（P0）基础热力图按日期展示完成任务数量，并提供非颜色信息或提示文本（FR-7.2）。
- [ ]（P1）燃尽趋势展示「剩余预估时长」随日期的变化，并提供理想参考线（FR-7.3）。
- [ ] 无预估时长的任务只计入任务数，不计入时长型燃尽图，并在界面说明（FR-7.4）。

### 2.8 FR-8 Windows 桌面能力（P0/P1）

- [ ]（P0）关闭按钮行为可配置为退出或最小化到托盘，首次触发时说明当前选择（FR-8.1）。
- [ ]（P0）托盘菜单提供显示主窗口和退出（FR-8.2）。
- [ ]（P0）保存窗口尺寸、位置和显示器信息；显示器不可用时恢复到主屏可见区域（FR-8.3）。
- [ ]（P1）精简悬浮窗展示最近截止目标和今日任务，并允许完成任务（FR-8.4）。
- [ ]（P1）支持自定义全局快捷键；发生冲突时提示重新设置（FR-8.5）。

### 2.9 FR-9 数据管理（P0/P1）

- [ ]（P0）可将全部业务数据导出为带版本号的备份文件并恢复（FR-9.1）。
- [ ]（P0）恢复前展示备份时间、目标数和任务数，并要求确认「合并」或「覆盖」（FR-9.2）。
- [ ]（P0）覆盖恢复前自动创建当前数据的安全副本（FR-9.3）。
- [ ]（P1）每日自动备份，默认保留最近 7 份；路径不可写时通知用户（FR-9.4）。
- [ ] API Key、日志和窗口状态不进入业务数据备份（FR-9.5）。

## 3. 用户流程走查清单（手动回归，每个里程碑结束时执行）

### 3.1 首次使用（PRD §5.1）

- [ ] 创建目标（名称 + 截止日期）后，首页立即出现目标卡片与正确倒计时。
- [ ] 可跳过计划偏好；默认每天 2 小时、每周 7 天。
- [ ] 手动添加任务的完整路径可用。
- [ ] 未配置 AI 时，手动计划闭环完整可用（FR-6 前置条件）。
- [ ] 数据为空时，页面提供与当前页相关的首个操作，而非纯说明页（PRD §8）。

### 3.2 每日执行（PRD §5.2）

- [ ] 打开应用后直接看到今日任务。
- [ ] 完成任务后，目标进度、热力图和剩余工作量立即更新。
- [ ] 当日未完成任务不会自动移动。
- [ ] 次日首次打开时，集中提示用户选择延期、重新安排或保留原日期，且由用户确认（FR-3.7）。

### 3.3 计划调整（PRD §5.3）

- [ ] 修改截止日期、每日可用时长或任务工作量后，剩余负载立即更新。
- [ ] 系统不擅自覆盖现有任务日期。
- [ ] 可查看冲突日期并手动调整；P1 可提供「均匀重排未完成任务」草稿。

## 4. 数据与迁移检查清单

- [ ] 每次 schema 变更都有 migration、升级前可验证备份/快照，以及升级成功和失败恢复测试（NFR-2）。
- [ ] 任务完成、任务延期、跨多表删除和 AI 草稿批量应用使用数据库事务（NFR-2）。
- [ ] 无半条写入：批量应用中途失败不会留下部分任务（FR-6.5）。
- [ ] 备份恢复先校验格式、版本、约束和关键计数，再通过事务合并或经校验的临时库原子替换；失败时原数据库保持可用（NFR-2）。
- [ ] 统计尽量由可验证的查询产生，不在多个状态对象中维护重复计数。
- [ ] 时间戳使用 UTC 存储，计划日期按本地日历日期单独存储（PRD §9）。
- [ ] 重复任务仅预生成未来 30 天实例，窗口临近时滚动生成（FR-4.3）。
- [ ] 覆盖恢复前自动创建当前数据安全副本（FR-9.3）。

## 5. 测试覆盖检查清单（按层、按变更范围）

本节只勾选当前变更涉及的实体、流程和风险项；不适用项应记录「N/A + 原因」。M3 起的里程碑验收需额外执行 §9 性能基线。

### 5.1 单元测试（纯 Dart service）

- [ ] 排程规则（含不可用日期、可用时长约束）。
- [ ] 负载计算（当日未完成预估时长之和）。
- [ ] 倒计时：跨日、跨年、DST。
- [ ] 建议日均时长与计划风险提示逻辑。
- [ ] 时长边界：1 分钟、1440 分钟、非法值。

### 5.2 DAO / Repository 测试（内存数据库）

- [ ] 当前变更涉及实体的 CRUD（Goal/Subject/Milestone/Task/ChecklistItem/RecurrenceTemplate/AIDraft/Settings）。
- [ ] 适用事务性操作：完成、延期、AI 草稿批量应用、删除目标（连带任务）。
- [ ] 查询正确性：今日任务、日历聚合、完成率、热力图数据。
- [ ] 数据库迁移成功、失败后原库仍可用，以及备份/快照恢复。

### 5.3 Widget 测试

- [ ] 创建目标 → 首页出现卡片与倒计时。
- [ ] 今日任务完成 → 列表、统计同步更新。
- [ ] 任务延期（含快捷默认延期至下一可用日）。
- [ ] 备份恢复入口与「合并/覆盖」确认流程。
- [ ] 删除目标二次确认对话框。

### 5.4 错误路径

- [ ] AI 返回非法 JSON / 超时 / 字段缺失时无脏数据。
- [ ] 草稿存在截止日之后的任务时被阻止应用并标出问题项。
- [ ] 非法预估时长输入的错误提示。
- [ ] 备份文件损坏或版本不匹配时的处理。
- [ ] 恢复校验或生效中断时，原数据库保持不变且可继续打开。
- [ ] 数据库异常时停止写入，提示从备份恢复或导出诊断信息（PRD §8）。

## 6. 代码审查检查清单（PR 提交前与审查时）

- [ ] 数据一致性：事务覆盖完成/延期/跨多表删除/AI 批量应用；备份恢复原子生效；无重复计数状态。
- [ ] 范围：未夹带无关重构；变更未超出本 PR 的 FR 范围。
- [ ] 许可证合规：新依赖/复制代码满足许可证声明要求，并已在借鉴决策记录表中登记（SOP 附录 C）。
- [ ] 隐私：日志、上报内容不含 API Key、完整请求正文或用户内容（NFR-3）。
- [ ] 可访问性：状态不只依赖颜色；控件有屏幕阅读器可识别名称；核心流程可键盘操作（NFR-4）。
- [ ] 性能：符合 NFR-1 基线；无明显可避免的重绘或全表扫描。
- [ ] 测试：涉及日期/时区、迁移、跨多表写入或备份恢复的改动已包含针对性测试。
- [ ] 文档：新增用户可见功能已同步更新 PRD 或相关文档（CONTRIBUTING 质量要求）。

## 7. 隐私与安全检查清单

- [ ] API Key 使用 Windows Credential Manager 或 DPAPI 保护，不使用设备指纹派生密钥（NFR-3）。
- [ ] 日志默认保存在本地，自动清理，保留不超过 14 天（NFR-3）。
- [ ] 发送诊断前展示将要发送的内容并征得用户确认（NFR-3）。
- [ ] AI 请求仅发送生成计划所需信息，不默认发送历史任务和日志（NFR-3）。
- [ ] API Key、日志和窗口状态不进入业务数据备份（FR-9.5）。

## 8. 可访问性与兼容性检查清单

- [ ] 核心流程支持键盘操作并具有清晰焦点状态（NFR-4）。
- [ ] 不仅依赖颜色表达完成、过载和错误状态（NFR-4）。
- [ ] 文本与背景对比度达到 WCAG 2.1 AA 目标（NFR-4）。
- [ ] 交互控件提供可被屏幕阅读器识别的名称（NFR-4）。
- [ ] 最低支持 Windows 10 22H2 及 Windows 11 64 位（NFR-5）。
- [ ] 已测试 100%、125%、150% 和 200% DPI（NFR-5）。
- [ ] 显示器插拔后的窗口恢复正确（NFR-5）。

## 9. 性能基线检查清单（M3 起每次验收）

- [ ] 冷启动至可操作界面：主流 Windows 设备上 ≤ 2 秒（NFR-1）。
- [ ] 今日任务常规操作反馈 ≤ 200 毫秒（NFR-1）。
- [ ] 10,000 条任务数据下，月历切换 ≤ 500 毫秒（NFR-1）。
- [ ] 性能达标不以牺牲数据正确性为代价（NFR-1）。

- [ ] 使用本次候选构建完成备份恢复演练：备份 → 修改数据 → 恢复 → 校验数据一致（FR-9 验收）。
- [ ] 覆盖恢复前自动安全副本已生效（FR-9.3）。
- [ ] 版本号、变更日志、已知限制已更新。

- [ ] P0 功能回归测试通过，无阻断级数据丢失或启动失败问题。

## 11. 里程碑门禁明细（M1~M5）

### M1 数据与目标闭环

- [ ] 目标、科目、任务 CRUD 完成。
- [ ] 本地数据库与 migration 模板建立，migration 测试通过。
- [ ] 应用重启后数据持久化一致。
- [ ] 删除目标二次确认（含删除任务提示）通过。
- [ ] 日期/时区关键边界测试（跨日、跨年、DST）通过。

### M2 每日执行闭环

- [ ] 今天页、日历视图可用。
- [ ] 任务完成、编辑、延期可用；快捷默认延期至下一可用日。
- [ ] 负载计算与「超出 X 分钟」提示正确。
- [ ] 「查看今日任务 → 完成/延期 → 查看更新后进度」可连续完成。

### M3 进度与数据保障

- [ ] 基础统计与热力图可用（含非颜色提示）。
- [ ] 手动备份/恢复可用，恢复前展示摘要并要求确认合并/覆盖。
- [ ] 覆盖恢复前自动安全副本生效。
- [ ] 托盘与窗口位置/多屏恢复可用。
- [ ] 备份恢复演练通过。
- [ ] 10,000 条任务性能达到基线（NFR-1）。

### M4 MVP 发布候选

- [ ] 无障碍检查（键盘、非颜色状态、对比度、屏幕阅读器）通过。
- [ ] P0 异常状态（无数据、过载、逾期、数据库异常）处理完整；若本候选包含 AI，再检查 AI 未配置和 AI 失败状态。
- [ ] 安装包构建与发布资产齐备。
- [ ] 回归测试通过，无阻断级数据丢失或启动失败。
