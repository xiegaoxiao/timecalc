# 时间计算器（TimeCalc）产品需求文档

> 版本：v0.4
>
> 状态：Windows MVP 需求基线，待 M1 启动评审
>
> 适用阶段：Windows MVP（M1～M5）
>
> 产品主张：把截止日期转化为今天可以完成的行动。

## 1. 文档目的

本文档用于统一 Windows MVP 的产品范围、核心规则和验收标准，可独立作为产品设计、开发和测试依据。未列入 MVP 的能力不作为首版交付条件。

## 2. 产品定义

### 2.1 用户问题

面临考试、论文或项目截止日期的用户，通常知道“最终要完成什么”，但难以持续回答以下问题：

1. 距离截止日还有多少可用时间？
2. 今天应该完成什么，工作量是否合理？
3. 计划落后后，如何低成本地重新安排？

TimeCalc 通过“目标倒计时 + 每日任务 + 进度反馈”解决上述问题。AI 是辅助排程能力，不是产品成立的前提。

### 2.2 目标用户

MVP 优先服务具有单个明确截止目标、计划周期为 7～180 天的个人用户，例如备考者、论文撰写者和个人项目执行者。

多目标并行、团队协作和跨设备同步不是 MVP 的优先场景。

### 2.3 产品原则

- **本地优先**：无账号、离线可使用全部非 AI 核心功能。
- **今天优先**：首页先回答“今天做什么”，再展示统计和长期计划。
- **计划可修正**：延期和调整是正常流程，不以惩罚性文案制造焦虑。
- **AI 可选且可撤销**：AI 只生成草稿，用户确认后才写入正式计划。
- **数据归用户所有**：支持导出、备份和恢复，不将用户内容默认上传。

## 3. 产品目标与衡量指标

### 3.1 MVP 目标

- 用户能在 3 分钟内创建目标并得到第一份可执行的每日计划。
- 用户能在 10 秒内查看、完成或延期一项今日任务。
- 用户修改截止日或任务状态后，剩余工作量与负载提示能立即更新。
- 无网络时，目标、任务、日历和统计仍可正常使用。

### 3.2 验证指标

首版不内置遥测时，可通过用户访谈和自愿提供的匿名统计验证：

| 指标 | 建议目标 |
|---|---:|
| 新用户完成“创建目标 + 创建首项任务”的比例 | ≥ 70% |
| 创建目标次日仍有任务操作的用户比例 | ≥ 35% |
| 今日任务完成或主动延期的比例 | ≥ 60% |
| 核心操作导致数据丢失的严重缺陷 | 0 |

以上数值是产品验证目标，不作为单机客户端的强制功能验收项。

## 4. MVP 范围

### 4.1 优先级定义

- **P0**：缺失则产品核心闭环不成立，必须随 MVP 交付。
- **P1**：明显改善体验，时间允许时随 MVP 交付，也可进入首个迭代。
- **P2**：后续版本候选，不阻塞 MVP 发布。

### 4.2 范围总览

| 模块 | P0 | P1 | P2 |
|---|---|---|---|
| 目标 | 倒计时、目标编辑/归档、逾期状态 | 里程碑 | 多目标综合负载 |
| 任务 | 增删改查、完成、延期、预估时长、日历 | 检查项、重复任务、批量操作 | 跨目标模板库 |
| 计划 | 手动排程、每日负载提示 | AI 生成草稿及确认 | AI 历史版本对比 |
| 反馈 | 今日概览、完成率、基础热力图 | 简单燃尽趋势 | 交互甘特图、PDF 报告 |
| Windows | 主窗口、托盘、窗口位置恢复 | 精简悬浮窗、全局快捷键 | 托盘动态图标、多屏高级规则 |
| 数据 | 本地存储、手动备份/恢复 | 自动备份 | ~~云同步、跨端同步~~（M9 曾交付 WebDAV 整库文件同步，v1.15 起移除，回到纯本地） |
| 其他 | 中文界面、浅色/深色主题（M10 已交付三选一：跟随系统/浅色/深色） | 键盘可达、英文界面 | 完整本地化体系 |

### 4.3 明确不做

MVP 不包含账号体系、团队协作、Android/iOS 客户端、复杂番茄钟、社交打卡、完整 RFC 5545 重复规则、用户自定义 system prompt。

> 2026-08-07（M9）：原「明确不做」清单中的**云同步**曾交付 WebDAV 整库文件同步（见 §11 说明）。账号体系、团队协作、多端客户端仍不在当前范围。
> **2026-08（v1.15）：移除全部 WebDAV 功能（整库同步、WebDAV 备份目的地、凭据存储），云同步回到「明确不做」；数据纯本地存储，多设备场景暂以手动备份/恢复承担。**

## 5. 核心用户流程

### 5.1 首次使用

1. 用户创建目标：名称、截止日期、可选描述。
2. 用户设置计划偏好：每周可用日、每日可用时长；默认每天 2 小时、每周 7 天，用户可跳过。
3. 用户选择手动添加任务，或在已配置 AI Provider 时选择 AI 辅助生成。
4. 系统进入计划预览；用户确认后生成任务。
5. 首页展示目标倒计时、今日任务和本周负载。

### 5.2 每日执行

1. 用户打开应用后直接看到今日任务。
2. 用户可完成、编辑或延期任务。
3. 完成状态立即影响目标进度、热力图和剩余工作量。
4. 当日未完成任务不会自动移动；次日首次打开时集中提示用户选择延期、重新安排或保留原日期。

### 5.3 计划调整

1. 用户修改截止日期、每日可用时长或任务工作量。
2. 系统重新计算剩余负载，但不擅自覆盖现有任务日期。
3. 用户可查看冲突日期并手动调整；P1 可提供“均匀重排未完成任务”草稿。

## 6. 功能需求与验收标准

### FR-1 目标与倒计时（P0）

#### 需求

- FR-1.1 用户可创建、编辑、归档和删除目标。必填项为名称与截止日期。
- FR-1.2 倒计时按用户本地日期计算，不按小时取整；截止日当天显示“今天截止”。
- FR-1.3 截止日已过且目标未归档时，显示“已逾期 N 天”。
- FR-1.4 用户可主动标记目标为“已完成”或“已放弃”，两者都停止逾期提醒。
- FR-1.5 一个任务必须属于一个目标，可选属于一个科目/分组。

#### 验收标准

- 创建合法目标后，首页立即出现目标卡片与正确倒计时。
- 截止日为今天、昨天和跨年日期时，显示结果正确。
- 删除目标前必须二次确认，并明确提示将同时删除其任务；归档目标不删除历史数据。
- 应用重启后，目标数据与状态保持一致。

### FR-2 里程碑（P1）

- FR-2.1 用户可在目标下添加、编辑、完成和删除里程碑。
- FR-2.2 里程碑日期原则上不得晚于目标截止日；若晚于截止日，保存前给出阻断提示。
- FR-2.3 首页仅展示距离最近的一个未完成里程碑，完整列表在目标详情中展示。

### FR-3 任务与日历（P0）

#### 需求

- FR-3.1 任务字段包括标题、计划日期、预估分钟数、完成状态、可选备注与科目。
- FR-3.2 用户可在今日列表或日历中创建、编辑、删除和完成任务。
- FR-3.3 用户可将未完成任务延期到指定日期；快捷操作默认延期至下一可用日。
- FR-3.4 日历显示每日任务数、完成数和预估总时长。
- FR-3.5 当日预估总时长超过用户设置的可用时长时，显示“超出 X 分钟”，不能只依赖红色表达。
- FR-3.6 用户可为历史日期补录任务和完成记录。
- FR-3.7 次日处理昨日未完成任务时，必须由用户确认，不自动改变原计划。

#### 验收标准

- 完成或延期任务后，今日列表、日历和统计在同一操作周期内同步更新。
- 预估时长仅接受 1～1440 分钟的整数；非法输入有明确错误提示。
- 延期操作保留任务内容、归属和预估时长，并记录原计划日期。
- 没有任务的日期不会显示为过载或完成率 0%。

### FR-4 检查项与重复任务（P1）

- FR-4.1 任务可包含可排序的检查项；任务完成时，未完成检查项需要二次确认。
- FR-4.2 重复规则首版仅支持每天、每周指定星期和每隔 N 天。
- FR-4.3 重复任务采用“模板 + 实例”模型，仅预生成未来 30 天实例，并在窗口临近时滚动生成。
- FR-4.4 修改重复规则时，用户必须选择“仅修改未来实例”或“仅修改模板”；已完成实例不得被覆盖。
- FR-4.5 停止重复后，不再生成新实例，历史实例保留。

### FR-5 手动计划与负载（P0）

- FR-5.1 用户可按日历拖动任务调整日期；拖动失败时恢复原位置并提示原因。
- FR-5.2 系统按“当日未完成任务预估时长之和”计算计划负载。
- FR-5.3 目标详情展示剩余任务时长、剩余可用天数和建议日均时长。
- FR-5.4 当建议日均时长超过用户设置的每日可用时长时，显示计划风险，并建议延长截止日、减少任务或增加可用时间。
- FR-5.5 系统只提出建议，不自动删除任务或修改截止日期。

### FR-6 AI 辅助生成计划（P1）

#### 前置条件

用户已自行配置受支持 Provider 的 API Key，且当前网络可用。没有 AI 时，手动计划闭环必须完整可用。

#### 需求

- FR-6.1 AI 输入至少包括目标、截止日期、任务/学习内容、每日可用时长和不可用日期。
- FR-6.2 强度选项使用“轻量、均衡、紧凑”，并展示对应负载解释；不使用“地狱”等带压力暗示的文案。
- FR-6.3 AI 输出必须先解析为结构化草稿，并校验日期范围、时长和必填字段。
- FR-6.4 用户可在草稿中编辑、删除、调整日期，并选择全部应用或取消。
- FR-6.5 只有用户确认后才写入正式任务；应用失败时不得写入部分计划。
- FR-6.6 AI 生成页面明确提示“生成内容可能不准确，请确认工作量与日期”。
- FR-6.7 连接测试只承诺验证鉴权和一次最小请求；余额和模型列表仅在 Provider 明确提供相应接口时展示。
- FR-6.8 网络不可用或未配置 Key 时，展示原因和手动排程入口，而非仅将按钮置灰。

#### 验收标准

- AI 返回非法 JSON、超时或部分字段缺失时，正式任务库不产生脏数据。
- 草稿中存在截止日之后的任务时，阻止应用并标出问题项。
- 用户取消草稿后，原有计划不发生变化。
- 日志不得记录 API Key、完整请求正文或用户隐私内容。

### FR-7 进度反馈（P0/P1）

- FR-7.1（P0）首页展示今日完成数/总数、今日已完成预估时长和目标剩余工作量。
- FR-7.2（P0）基础热力图按日期展示完成任务数量，并提供非颜色信息或提示文本。
- FR-7.3（P1）燃尽趋势展示“剩余预估时长”随日期的变化，并提供理想参考线。
- FR-7.4 无预估时长的任务只计入任务数，不计入时长型燃尽图，并在界面说明。

甘特图、年份热力图、PNG/PDF 报告导出列为 P2。MVP 先验证任务执行闭环，避免图表开发挤占核心体验。

### FR-8 Windows 桌面能力（P0/P1）

- FR-8.1（P0）关闭按钮的行为可配置为退出或最小化到托盘，首次触发时说明当前选择。
- FR-8.2（P0）托盘菜单提供显示主窗口和退出。
- FR-8.3（P0）保存窗口尺寸、位置和显示器信息；显示器不可用时，将窗口恢复到主屏可见区域。
- FR-8.4（P1）精简悬浮窗展示最近截止目标和今日任务，并允许完成任务。
- FR-8.5（P1）支持用户自定义全局快捷键；发生冲突时提示重新设置。

托盘图标动态显示剩余天数列为 P2。Windows 托盘图标不具备原生 badge，动态绘制还会带来小尺寸可读性和缓存问题。

### FR-9 数据管理（P0/P1）

- FR-9.1（P0）用户可将全部业务数据导出为带版本号的备份文件并恢复。
- FR-9.2（P0）恢复前展示备份时间、目标数和任务数，并要求确认“合并”或“覆盖”。
- FR-9.3（P0）覆盖恢复前自动创建当前数据的安全副本。
- FR-9.4（P1）支持每日自动备份，默认保留最近 7 份；路径不可写时通知用户。
- FR-9.5 API Key、日志和窗口状态不进入业务数据备份。

## 7. 信息架构

主导航保持四个一级入口：

1. **今天**：倒计时、今日任务、过载提示和快速添加。
2. **计划**：日历、目标、科目、里程碑和任务调整。
3. **进度**：完成趋势、热力图和燃尽趋势。
4. **设置**：计划偏好、外观、AI Provider、备份与快捷键。

首页不重复展示全部图表。目标详情遵循“目标概览 → 里程碑 → 任务”的层级，避免同时堆叠目标、科目、统计和甘特图。

## 8. 关键状态与文案

| 状态 | 行为 |
|---|---|
| 今日无任务 | 展示“今天没有安排”，提供添加任务和查看后续计划入口 |
| 任务过载 | 展示超出分钟数，并提供调整任务入口 |
| 目标逾期 | 展示逾期天数和“调整截止日/完成目标”操作 |
| AI 未配置 | 解释需要配置 Provider，同时保留手动创建计划入口 |
| AI 失败 | 保留用户输入，给出重试和手动编辑入口 |
| 数据为空 | 提供与当前页面相关的首个操作，不使用纯说明页 |
| 数据库异常 | 停止继续写入，提示从备份恢复或导出诊断信息 |

## 9. 数据模型概要

所有业务实体包含 `id`、`createdAt`、`updatedAt`。时间戳使用 UTC 存储，计划日期按本地日历日期单独存储，避免跨时区导致日期漂移。

### Goal

`title`, `description?`, `deadlineDate`, `status(active/completed/abandoned/archived)`, `completedAt?`

### Subject

`goalId`, `name`, `color`, `sortOrder`

### Milestone

`goalId`, `title`, `date`, `status`, `sortOrder`

### Task

`goalId`, `subjectId?`, `recurrenceTemplateId?`, `title`, `note?`, `plannedDate`, `originalPlannedDate?`, `estimatedMinutes?`, `status(todo/done)`, `completedAt?`, `sortOrder`

### ChecklistItem

`taskId`, `title`, `done`, `sortOrder`

### RecurrenceTemplate

`goalId`, `subjectId?`, `title`, `estimatedMinutes?`, `ruleType(daily/weekly/interval)`, `ruleJson`, `startDate`, `endDate?`, `active`, `generatedThroughDate`

### AIDraft

`goalId`, `provider`, `model`, `inputSummaryJson`, `planJson`, `status(draft/applied/discarded)`, `error?`

### Settings

`dailyAvailableMinutes`, `availableWeekdays`, `theme`, `language`, `closeBehavior`, `backupPath?`, `autoBackup`, `hotkeysJson?`

## 10. 非功能需求

### NFR-1 性能

- 冷启动至可操作界面：主流 Windows 设备上目标 ≤ 2 秒。
- 今日任务常规操作反馈：目标 ≤ 200 毫秒。
- 10,000 条任务数据下，月历切换目标 ≤ 500 毫秒。

具体指标应在确定最低支持设备后复核，不以牺牲数据正确性换取响应速度。

### NFR-2 可靠性

- 任务完成、延期和批量应用 AI 草稿使用数据库事务。
- 删除目标等跨多表破坏性操作必须具备原子性，失败时不得留下孤立或半删除数据。
- 数据结构升级必须提供 migration 测试和失败恢复策略；升级前保留可验证的数据库备份或快照，失败时不得继续使用部分迁移的数据。
- 备份恢复必须先完成格式、版本和数据校验，再以事务或经校验的临时库替换方式生效；失败时保持原数据库可用。
- 应用异常退出后，不得出现半条任务或统计与任务状态不一致。

### NFR-3 安全与隐私

- Windows 端 API Key 使用 Windows Credential Manager 或 DPAPI 保护，不使用“设备指纹派生密钥”。设备指纹通常可预测，也会因硬件变化导致无法解密。
- 日志默认保存在本地，自动清理，保留不超过 14 天。
- 发送诊断前展示将要发送的内容并征得用户确认。
- AI 请求仅发送生成计划所需信息，不默认发送历史任务和日志。

### NFR-4 可访问性

- 核心流程支持键盘操作并具有清晰焦点状态。
- 不仅依赖颜色表达完成、过载和错误状态。
- 文本与背景对比度以 WCAG 2.1 AA 为目标。
- 交互控件提供可被屏幕阅读器识别的名称。

### NFR-5 兼容性

- MVP 最低支持版本暂定 Windows 10 22H2 及 Windows 11 64 位。
- 应明确测试 100%、125%、150% 和 200% DPI，以及显示器插拔后的窗口恢复。

## 11. 技术约束与建议

建议技术栈为 Flutter/Dart、SQLite + drift、Riverpod 和 GoRouter，但产品验收以用户行为和数据正确性为准。

具体的开源项目、可借鉴模块和许可证边界见 [开源项目借鉴清单](open-source-references.md)。该清单仅提供实现参考，不改变本 PRD 的功能优先级。

- 重复任务不要一次生成无限实例，采用有限窗口滚动生成。
- AI 输出使用 JSON Schema 或等价结构校验，禁止直接把自然语言结果写入数据库。
- Provider 层采用统一接口，但首版只支持 1～2 个经过测试的 Provider，避免承诺任意兼容。
- 本地优先不等于提前建设同步框架；先使用稳定 ID、时间戳和 schema version 保留演进空间。**M9 曾落地 WebDAV 整库文件同步**（整库快照为同步单元、后写者胜），**v1.15 已整体移除**（见 §12 M9 备注）；业务实体仍保留 id/时间戳/schema version，为未来可选的同步方案保留演进空间。

## 12. 版本计划与退出条件

### M1：数据与目标闭环

交付目标、科目、任务、本地数据库和 migration。退出条件：目标与任务 CRUD、重启持久化、删除确认和关键边界测试通过。

### M2：每日执行闭环

交付今天页、日历、完成、延期和负载计算。退出条件：用户可连续完成“查看今日任务 → 完成/延期 → 查看更新后进度”。

### M3：进度与数据保障

交付基础统计、热力图、手动备份恢复、托盘与窗口恢复。退出条件：备份恢复演练通过，10,000 条任务性能达到基线。

### M4：MVP 发布候选

完成无障碍、异常状态、安装包和回归测试。退出条件：P0 验收全部通过，无阻断级数据丢失或启动失败问题。

### M5：首个增强迭代

根据 MVP 验证结果选择交付 AI 草稿、重复任务、检查项、燃尽趋势、自动备份和精简悬浮窗。P1 不应在缺少用户验证时同时全部启动。

### M6：任务检查项（FR-4.1）

交付任务可排序检查项 + 完成二次确认 + 级联删除。退出条件：检查项 CRUD/排序/级联删除测试通过。

### M7：燃尽趋势（FR-7.3）

交付「剩余预估时长」随日期变化的燃尽趋势 + 理想参考线。退出条件：口径与边界测试通过。

### M8：每日自动备份（FR-9.4）

交付本地目录自动备份（保留 7 份、应用运行期间语义、从备份位置恢复）。退出条件：备份/保留策略/恢复链路测试通过。
> 备注：M11 起目的地收敛为本地目录；v1.15 移除 WebDAV 后仅存本地目录。

### M9：WebDAV 整库文件同步（云同步落地）

交付多设备数据同步：整库快照为同步单元（后写者胜），触发 = 启动拉取 / 变更推送 / 退出推送 / 手动 / 每 5 分钟周期复查；远端仅存最新一份快照 + meta（seq/schema 版本），拉取覆盖前自动安全副本，运行时配置各设备独立。退出条件：同步服务（拉取/推送/seq/版本守卫/互斥）+ 覆盖恢复保留 + 迁移测试通过。
> **备注（v1.15）：该功能已整体移除**——同步页、同步服务、`DatabaseChangeWatcher`、WebDAV 备份目的地与凭据存储全部下线，`settings` 表 6 个 WebDAV/同步列经 schema v13 迁移删除；数据回到纯本地单机，多设备场景以手动备份/恢复承担。本里程碑条目保留作历史记录。

### M10：明暗主题切换（外观页落地）

交付外观设置：跟随系统 / 浅色 / 深色三选一，保存即换肤无需重启；主题模式为设备级配置（schema v12 `theme_mode`），不进入业务备份（FR-9.5），覆盖恢复时保留本设备选择。退出条件：换肤链路 + 覆盖恢复保留 + 迁移测试通过。

## 13. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| MVP 功能继续膨胀 | 延期且核心流程质量下降 | 以 P0 退出条件锁定范围，P1 逐项验证后进入迭代 |
| AI 计划质量不稳定 | 用户误信错误安排 | 草稿预览、结构校验、负载校验、人工确认、失败不落库 |
| 重复任务产生大量实例 | 数据膨胀、修改语义混乱 | 30 天滚动生成，明确模板与实例边界 |
| 日期和时区错误 | 倒计时或任务错位 | UTC 时间戳与本地日期分离，覆盖跨日/跨年/DST 测试 |
| Windows 多屏与 DPI 差异 | 窗口不可见或布局异常 | 保存显示器信息，恢复时校正到可见区域，覆盖多 DPI 测试 |
| 备份不可恢复 | 用户对本地优先产品失去信任 | 备份版本校验、恢复预览、覆盖前自动安全副本、定期演练 |
| Provider 接口差异 | 连接测试或模型能力不可用 | 首版限定 Provider，能力检测按接口可用性降级 |

## 14. 上线前待确认事项

- 最低支持的 Windows 版本和最低测试设备配置。
- MVP 是否完全不采集使用数据；若采集，需另行定义隐私说明、开关和事件字典。
- 首版是否包含 AI。建议核心 P0 稳定后，将 AI 作为可关闭的 P1 功能灰度验证。
- 首发安装与更新方式，以及是否需要代码签名。
- 用户删除目标后的恢复策略：MVP 可采用二次确认，后续可评估回收站。

## 15. 版本变更摘要

### v0.4（相较 v0.3）

- 明确跨多表删除、数据库迁移和备份恢复的原子性与失败恢复要求。
- 明确迁移失败时不得继续使用部分迁移数据，避免把“回滚策略”误解为直接降级数据库 schema。

### v0.3（相较 v0.2）

- 将文档改为自包含版本，不再引用缺失的 FR-1.1～FR-4.5 或 M1～M6。
- 明确 Windows MVP 的 P0/P1/P2 边界，将甘特图、PDF 报告等高成本能力后移。
- 聚焦“创建目标 → 安排任务 → 每日执行 → 调整计划 → 查看反馈”的核心闭环。
- 为关键功能增加可测试的验收标准、异常状态和数据一致性要求。
- 将 AI 定位为可选草稿工具，补充结构校验、事务写入、隐私和降级规则。
- 将 API Key 存储方案调整为 Windows Credential Manager/DPAPI。
- 补充产品指标、明确非目标、数据模型、里程碑退出条件和上线待确认事项。
