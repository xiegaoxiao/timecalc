## 0 结论摘要

- **整个模块建议「保留」，但建议大幅收窄**：不建议移除。PRD §4.2（`docs/requirements.md:78`）把「课程增删改查、教学周网格、周次切换、`.ics`/JSON 导入」放在**课表行的 P0 列**，而 §6 FR-10（`:225-234`）六条又全部标 (P1)——PRD 自相矛盾；按较严的读法，模块骨架已在 MVP 范围内，且删除要新增一次 drop 迁移并清掉 66+ 用例，代价远高于收益。
- 收窄的可操作对象不是「单双周/撞课并排/导入派发」这些 **P1 列与 FR-10.4 明文要求**的机制（它们是规格内复杂度，判定必留或可留），而是 **PRD 完全没有要求的自选复杂度**：当前时间指示线（约 60 行）、12 节双真相源（B19）、4 类共 5 个生产零引用符号（B24）、JSON 侧中文别名（约 45 行）、400ms 防抖 + 256KB isolate 阈值（B20），合计约 250-300 行可减。
- 成本分布：导入解析 `timetable_import_parser.dart` 711 行占模块 22%（ICS 启发式 ≈334 行、JSON ≈196 行），课表页 954 行次之；DB 侧 15 列 + v17 迁移 21 行；「删除影响面」主要落在 schema/迁移、备份格式与 4 个测试文件，而非运行时。
- 与「计划」的重叠**不是 UI 网格重叠，而是数据与语义重叠**：`planning_repository.dart:70,116-146` 把课程行换算成排程占用、`planning_service.dart:1281` 用课程时长扣减当日容量——这与 FR-10.6「不参与任务负载」的口径冲突，也让 PRD §7「互补而不重叠」的声明在当前工作区失效（见 §4 存疑 2）。
- 另有 2 处「两份实现」：单双周语义（`course_week.dart:64-74` vs `planning_service.dart:785-799`）与周次日期范围文案（`timetable_page.dart:535-541` vs `calendar_view.dart:443-453`）。
- 置信度：B1~B10、B12~B19、B24、B25 为 **高**；B11、B20~B23、B26 为 **中**（B26 与 planning 相关的结论中，原因之一是无法在不触碰 git 的前提下确认这些改动是否已提交，见 §4 存疑 6）。

## 2 逐条论证

**B1 课程 CRUD**：这是模块的地基，`CourseRepository` 没有状态流转、没有延期/完成，189 行里 60 行是边界夹取与事务，属于「必要且没有更简单写法」。注意到 `create`（`:48-79`）只是 `createFromDraft` 的薄封装，表单页两条路径其实都走 `createFromDraft`，留一层可读性封装不算冗余。详情对话框（B21）是唯一可省的一层。判必留。

**B2 网格**：`_TimetableGrid` 76 行做列宽下限 + 横向滚动，`_DayColumn` 55 行做 Stack 定位与行分隔线，`_buildPeriodLabels` 39 行。三个都不是可省的抽象层，且与 PRD FR-10.2 的四个要素一一对应。唯一可讨论的是 `span >= 4 ? 2 : (span >= 2 ? 1 : 0)` 的副行密度策略（`:887-894`，8 行），它让 1 节卡片不显示地点/教师——属于精细但廉价的取舍，不值得动。

**B3 周次切换**：`course_week.dart` 99 行是纯函数 + 单测覆盖跨月/跨年/未开学边界，「不存绝对日期、只存教学周号」是这套设计里最省的做法（`tables.dart:246-248` 的注释说清了理由）。若删掉基准，整张网格只能显示「全部课程」，FR-10.3 直接失效。判必留。

**B4 双格式导入**：711 行里真正的格式判别只有 5 行（`:118-124`），主要体量在字段解析。这里值得注意：**PRD 明文要求**双格式（§4.2:78 P0 列 + FR-10.4），因此「两种导入格式」本身不是镀金；可裁的是格式内部的自选容错（B10/B11/B20）。ICS 侧复用 `IcsCodec` 而非重写（`:107`），这是本模块最值得表扬的复用点。判必留。

**B5 替换/追加 + 事务**：`importCourses` 17 行即把「替换不翻倍」与「失败回滚」都做实（`:161-174`），验收标准 `:240` 与测试 `course_repository_test.dart:211-270` 直接对应。这是低成本高价值，无裁剪空间。判必留。

**B6 预览**：预览本身 54 行（`_CoursePreview`），加上问题列表与状态行共约 100 行，换来「校验不通过不写入任何数据」这一 NFR-2 承诺的可视化。PRD 明文要求，判必留。

**B17 门数/节数摘要**：15 行纯计算，`_periodCountOf`（`:207-209`）与筛选后的 `visible` 一致，不会撒谎，且已有断言 `timetable_page_test.dart:137-138`（`'· 1 门课 · 2 节'`）。PRD 没要求，但成本近零且给用户「这周有几门课」的即时反馈，属无害的自选项；删除需同步改该断言，收益不成比例。判可留。

**B18 清空课表**：`_clearAll` 27 行包含不可逆二次确认，且验收标准 `:241` 明确写「『清空课表』不动任务、目标与学期基准」——删掉这个入口会让一条验收标准失去对应物。判必留。

**B20 防抖与 isolate**：400ms 防抖 + 序号防过期（`:81-84,119-124`）是 20 行换来「打字时不闪」的顺滑，属于典型可留可不留；256KB isolate 阈值（`:58`）更可疑——课表 ICS 每门课约 10 行文本，一份 20 门课的 ICS 不到 20KB，跨 isolate 传字符串的收益几乎为零，而它要求解析器保持纯 Dart 无 Flutter 依赖（这条约束本身有价值，见 §3）。判建议简化或合并（删 isolate 分支，防抖保留与否看 UX 偏好）。

**B22 排程回显**：46 行复用 `ClassPeriods.rangeLabel/timeRangeLabel` 与 `weekRangeLabel`，是「让用户在下笔时核对语义」的廉价手段（表单复杂度的对手是填错格子后回网格找错误）。判可留。

**B23 双份单双周实现**：`course_week.dart:64-74` 与 `planning_service.dart:789-798` 是同一条规则的两次实现，后者注释里自己承认「与 … 同语义」。这种重复的危险不是今天的 LOC，而是明天改一处忘一处（例如把「未知取值按每周」改成按单周）。收敛方向是让 plan 侧复用 `WeekParity`/`weekParityMatches`。判建议简化或合并，写权需与 plan 分区协调。

**B25 跨模块重复**：`_formatRange`（`timetable_page.dart:535-541`）与 `calendar_view._weekTitle`（`:443-453`）是同一段「M月D日 – D日，跨月补月」逻辑的两份实现；星期标签在 `course_week.dart:15`、`calendar_view.dart:914,1362`、`progress_page.dart:1235`、`today_page.dart:575` 共 5 份。单看课表的份额不大（6 行 + 1 份常量），但这是「奥卡姆剃刀找冗余」里收益最确定的一类，前提是 lead 同意跨分区合并。判建议简化或合并。

## 3 明确不建议动的部分

1. **`IcsCodec` 复用与 `plan_file_picker` 复用**：`timetable_import_parser.dart:107` 与 `timetable_import_dialog.dart:93` 分别复用日历编解码器与计划文件选择器，`ImportIssue`（`:23`）也复用任务导入的问题类型。这是「两种导入格式」没有变成两套 IO 栈的原因，动它只会增加重复。
2. **课程与任务分表**：`tables.dart:231-249` 明确课程不是可延期任务，独立表避免了「课程被当成待办」。合并进 Tasks 是反向优化。
3. **v17 迁移的显式索引补建**（`database.dart:385-388`）：`Migrator.createTable` 不建 `@TableIndex` 索引，代码显式补 `CREATE INDEX IF NOT EXISTS`，并配了半迁移幂等测试（`migration_test.dart:1288`）。这是低成本高价值的正确性细节。
4. **作息表硬编码而非可配置**：`class_period.dart:46-59` 是常量表。改成用户可配置（多校区/多套作息）才是镀金；现状是最小实现（只需修 B19 的双真相源）。
5. **备份 codec 的宽容兜底**（`backup_codec.dart:325-352`）：对缺字段的课程对象给默认值而不是失败，与旧备份兼容策略一致，`backup_service_test.dart:247-272` 有对应回归测试。不要为了「严格」收紧。
6. **`course_week.dart` 的纯函数与其 16 个用例**：跨月/跨年/未开学/脏 parity 都有覆盖，是模块里测试质量最高的一块。
7. **不可逆操作的二次确认**：「清空课表」（`timetable_page.dart:267-283`）与单门课程删除（`course_detail_dialog.dart:129-145`）的确认对话框，以及替换导入的单事务回滚（`course_repository.dart:161-174`）——这些确认与回滚成本换取的是「不会静默丢课表」，应保留。

## 4 存疑项（需要用户拍板）

**存疑 1：学期基准是否由导入自动写回（B10）**
- 选项 A（现状）：导入 ICS 推导出基准就直接写库，SnackBar 事后告知。代价：用户导入第三方课表会静默改变自己整学期的周号基准，网格整体位移一周也不会有二次确认。
- 选项 B：预览里显示「推导出第 1 周周一 = 2026-09-07」，默认不写，用户勾选后才写。代价：多一次交互、多一个复选框与 1 个测试改动；好处是把全局状态变更交回用户。
- 建议 B。需在裁剪排期里单独安排，因为它触及 `settings` 与 1 个 widget 测试。

**存疑 2：课程占用参与排程 vs FR-10.6「不参与任务负载」（B26）**
- 选项 A（现状）：课程时长从当日可用容量中扣减（`planning_service.dart:1281`），FR-10.6 与 `app_refresh.dart:75-78` 的措辞作废，需改 PRD 与注释。代价：改动面小（文档 + 注释），但「课表不影响计划」这一边界承诺永久消失。
- 选项 B：课程占用作为「智能重排」的可关选项（默认开）。代价：多一个 Settings 字段 + 迁移 + 备份字段 + 开关 UI，违反「不新增设备/学期配置」的既有取向。
- 若用户认可 A，本模块与 plan 分区的重叠结论应改写为「有意整合」而非「冗余」。

**存疑 3：模块整体是否真的在 MVP/P0 范围内**
- 选项 A（保留，本报告默认）：按 §4.2:78 课表行 P0 列读，模块骨架属 MVP，现有 66 用例与 v17 迁移构成沉没成本，只做 B10/B16/B19/B20/B21/B24/B25 的收窄。
- 选项 B（整模块降级到「可选插件」）：若用户认为 §4.2 的 P0 列是笔误、§6 的 (P1) 才是真意，则可行方向是把课表从主导航移到「设置 → 附加功能」，保留课程 CRUD + 网格，冻结导入启发式（B8/B9/B10）不再维护。代价：主导航从 6 项变 5 项（`app_router.dart:103`、导航标签）、PRD §7 改写、`timetable_page_test.dart` 的导航 helper 需改；好处是冻结 711 行解析器的维护面。

**存疑 4：单双周 / 撞课并排 / 导入启发式是否算「规格级镀金」**
- 这三项在代码层都判必留/可留（PRD 三处明文 + M17 退出条件），但它们的总成本（约 150 行代码 + 3 组测试 + 1 个 schema 列）来自 PRD 自身的过度规格。若用户愿意把奥卡姆用到 PRD 层：
